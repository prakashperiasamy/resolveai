# ResolveAI five-minute walkthrough

Designed and built by **Prakash Periasamy**. Open `demo/index.html`, or run the editable application with `npm ci` and `npm run dev`.

1. **Command center:** inspect the 68 open synthetic cases, blocked work, critical impact, QA exposure, and the five-year trend.
2. **Escalations:** filter by severity and stage. Search a fictional customer, owner, or case ID. Select a case to inspect its context and event timeline.
3. **Ask ResolveAI:** try “Which cases are blocked?”, “What is waiting for QA?”, or “Show critical aging cases.” Inspect the returned counts and linked cases. Responses use deterministic keyword rules, not a live language model.
4. **Release path:** select a stage to inspect the associated active cases. This is visibility into illustrative handoffs; it does not change an external workflow.
5. **History:** search the full 2,700-case synthetic inventory. Review the 60-month history rather than interpreting it as measured customer data.
6. **Export:** download the filtered CSV and confirm the rows match the current selection. Generated notes are local drafts and do not send messages.

The snapshot is September 28, 2026. Every customer, person, case, and outcome is fictional. State resets on reload. No Jira or equipment system is connected. See the executive brief for the proposed production design.
